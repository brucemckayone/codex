# Per-look critique — 8 read-only design agents, one per look

Each agent resolved ONE look's nine axis values and traced them through all
eleven section components. This is the cut the per-file pass could not make:
those eleven agents each saw one component across all eight looks, and a page
is experienced as a whole.

**These are critiques, not applied changes.** Several are architectural and
need a human decision — three of them change how 695 live pages resolve.

8 looks critiqued · 104 defects (45 high impact) · 56 proposed deletions · 49 candlelit-blocked

## The finding that reframes the whole programme

**The look picker is close to inert on a real page, and VERIFIED as such.**

`section-design-defaults.ts:259` stores each section's rhythm as a DIFF against
the look active at creation:

```js
if (inherited && inherited[key] === value) continue;
```

and `page-builder-store.svelte.ts:434` moves the look afterwards without
re-diffing:

```js
function setPageDesign(design) { state.pending.design = { ...design }; }
```

Both lines confirmed by reading them. Consequences:

- **A page can have a rhythm OR a look, never both.** Create under look X and
  every axis where the rhythm agreed with X is omitted; switch to Y and those
  axes silently inherit Y.
- This *undoes the file's own stated purpose*. Its header says it exists to end
  "`surface: media` applied even to `ache` and `map`, which have no media at
  all" — but create under a `bare` look (so `surface: bare` matches and is
  omitted), switch to Candlelit, and `ache` inherits `media` again.
- On a template-seeded page, **69 of 99 axis slots are overwritten by the type
  table**; the look alone decides 7, and all 7 are `media` — on the seven
  sections that read zero `--jp-media-*` properties. The picker is decorative
  there.
- On the **695 backfilled production pages** there are no section `design` keys
  at all, so all eleven sections resolve identically: one padding (70px), one
  surface (transparent), zero borders, nine identical headings.

**This is a bigger cause of "seven looks read the same" than the atmosphere
gap I fixed in `965e0539`.** It also needs a decision, because any fix changes
what 695 live pages render. Three candidate fixes, in the doc's view of
increasing invasiveness:

1. **Re-diff on look change.** `setPageDesign` recomputes each section's rhythm
   against the NEW look. Preserves the "Inherited" pill semantics. Needs a way
   to tell a rhythm-written axis from a creator-authored one — recoverable by
   diffing against the OLD look, but a heuristic.
2. **Store the rhythm ABSOLUTELY** (all nine axes, always). Simple and
   look-independent, but the file's note (2) rejects it because a redundant key
   makes the inspector's "Inherited" pill lie.
3. **Mark provenance in the schema** (which axes were written by the table).
   Correct, most invasive, and a migration.

## Second finding, already FIXED

`CtaLink.svelte` read **zero** `--jp-*` tokens, so the `accent` axis — "how the
brand colour is used" — reached no call-to-action anywhere, in Hero, Feel,
Invite or FloatingCta. Candlelit's own signature never touched the button a
buyer clicks. Fixed: the CTA now reads the accent ladder with the semantic pair
as a fallback. Measured no-op at the two filled values (`--jp-accent-fill`
computes to `#A62B0C`, which IS `--color-brand-primary`).

Related and NOT fixed: agents report that Candlelit's glow paints nothing on
four of the six elements that read `--jp-accent-glow`, because the spread
annihilates it at control scale. Unverified by me.

## Per-look verdicts


### Candlelit

**Verdict.** Candlelit reads better than the other seven because it is the only look with light in it — not because it is composed. On the 695 backfilled pages every section resolves the same nine values, so the page is eleven transparent boxes at identical 70px block padding with no border, no shadow, no surface change and no radius; the only things separating section N from section N+1 are 140px of air and a bloom anchored at x=50% in seven of eleven sections. Worse, the look's own signature — THE BLOOM — paints literally nothing on four of the six elements that read `--jp-accent-glow` (the spread annihilates it at control scale, provably at every brand density) and never touches a single CTA, because `CtaLink.svelte` reads no axis token at all. So the honest answer is: it is the least flat of eight flat looks, and it does not yet read as designed.

**Worst problem.** /Users/brucemckay/development/Codex/apps/web/src/lib/page-builder/section-design-defaults.ts:259 — `if (inherited && inherited[key] === value) continue;` makes the stored per-type rhythm a DIFF against whichever look was active at creation, and `page-builder-store.svelte.ts:437` moves the look afterwards without re-diffing. A Candlelit page can therefore have a rhythm or a look, never both: created-then-switched, Candlelit's `align:center` + `type:monumental` + `surface:media` + `edge:none` leak into the six middle sections the table wanted `start`/`balanced`/`panel`/`hairline` for; created-under-Candlelit, the table wins all nine axes on all eleven sections and the look becomes literally inert (its only surviving axis is `media`, on the seven types that consume none of `--jp-media-*`).

**Read as a whole page.** It does not breathe, and on the production page it cannot. `section-design-defaults.ts` is a real rhythm on paper — the density column reads vast·airy·regular·regular·regular·airy·regular·compact·regular·compact·vast and the surface column media·bare·tint·media·media·bare·panel·panel·tint·bare·invert — but that table is CREATION-ONLY (its own note 4), and both `ReelSection.svelte:1425` and `TurnSection.svelte:573` record that all 695 backfilled pages carry the flat Candlelit bag with no section `design` keys. So the shipped page is: eleven sections × `density:airy` → `--jp-sec-pad-block` clamps to exactly 70px on all eleven at desktop; eleven × `surface:media` → `--jp-sec-bg: transparent` on all eleven, so there is no surface alternation at all and `.jp-sec`'s `isolation: isolate` means the blooms cannot even bleed into each other to fake a transition; eleven × `edge:none` → zero borders, zero shadows; nine × `type:monumental` on `.jp-sec__heading--sub` → nine identical 48px/`leading-none` headings; eleven × `align:center` fighting 23 hardcoded `text-align: left|start` declarations inside the cards, so every one of the eleven screens is a centred header over a left rag and the reading axis resets eleven times. Where the eye IS led, it is led by the only axis that varies anything: `media:bleed`'s 21/9 bands in the four sections that consume `--jp-media-*` (Hero, IntroVideo, Reel, Guide). Those four punctuate genuinely. The other seven are interchangeable centred slabs, and I could reorder them without a viewer noticing. The atmosphere makes it worse rather than better: seven of eleven blooms are anchored at x=50% (Ache:655 50/50, Turn:432 50/50, Map:1074 50/34, IntroVideo:920 50/46, Hero:870 50/46, Invite:1097 50/46, Proof:584 50/0, Guide:944 50/55) so the light never moves down the page — it pulses in the same place eleven times. Only Feel (12%/0%) and Reel (26%/34%) break the column. Fix the two cheapest things and the page starts to build: alternate the bloom origin, and let the section h2 breathe.

### WHERE I DISAGREE WITH THE CRITIQUE

**The recommendation to delete ~417KB of comment prose is wrong for this
codebase, and I am not doing it.**

The reasoning offered — 65% of the section tree is prose, therefore it is "now
actively harmful" — treats byte count as the defect. I checked the actual blocks.
Taking `ProofSection`'s 1,234B atmosphere comment as representative: exactly ONE
sentence restates the ladder. The rest is section-specific and not recoverable
from anywhere else —

> "this bloom is `--jp-accent-mark` at 9% and 9% is already the faintest thing
> the section paints … `panel`'s 0.18 lands on a 1.6% wash … `x * (2 - x)` was
> chosen for its ENDPOINTS rather than its shape: exactly 0 at 0 and exactly 1
> at 1."

That is the arithmetic behind a non-obvious `calc()`, and it is why a future
editor will not linearise it and quietly kill the layer on three looks. So the
genuinely removable text is ~120 bytes per block (~1.3KB across eleven), not
26KB — and eleven risky edits for 1.3KB is a bad trade.

More generally: the prose in this tree is load-bearing in a way it is not in most
repos. It records measurements, contract IDs and why-not decisions, and the
session that produced this document watched it prevent regressions repeatedly —
A64's `0px`-vs-`0` unit trap, `e32xz`'s cancelled `waitUntil`, the
`--jp-accent-fill: transparent` case that would have shipped an invisible CTA.
The owner asked for a UI simplification run, which means simpler UI and simpler
code. It does not mean fewer comment bytes.

gutter floors (safe, above); the eleven byte-identical section-root box recipes,
hoisted into `journey-sections-shared.css`, which already sets that precedent

`InviteSection`'s dead `border`+`outline` pair, whose premise A64 removed — that
